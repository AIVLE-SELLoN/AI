## 1. 공통 설정

| 항목 | 값 |
| --- | --- |
| 채널 | 쿠팡 / 네이버 / 지그재그 |
| 판정 윈도우 | 현재 = 최근 7일 / 과거 기준 = 직전 28일 (알림 발행 구간 제외) |

| 탐지 방식 | 채널별 "현재 vs 자기 과거" **Fisher 단측 검정 단일**, 유의 채널 수로 편중/전역 |
| 유의수준 α | 0.05 |
| 최소표본 | 현재 윈도우 **(상품, 채널) 총문의**(= 분모, aspect 무관) <10 → 판정 보류(이월), 채점 제외. **보류는 채널 단위** |

| 다중비교 보정 | **BH-FDR 필수 (q=0.05).** family = 같은 윈도우의 **상품별 전체 검정**(최대 36, 보류 채널 제외). 1,464는 정본 평가 윈도우의 전체 검정 수이지 family 크기가 아니다. `q`는 BH 가정 아래 상품별 기각 집합의 기대 FDR 목표이며, 최종 운영 헛알림률 5%를 직접 보장하지 않는다. |
| 채점 기준 | **본채점은 oracle** — 분류기를 거치지 않고 golden 라벨 카운트를 검정에 직접 입력 |

### G. 경계선 (채점 제외, 민감도 관찰) BH 임계 기준으로 재배치

**경계의 정의가 바뀌었다.** BH 도입 전에는 "raw p 0.05 경계"였으나, 이제는 **BH 실효 컷오프 근처**여야 경계로 기능한다.

**G 배치에는 두 가지 함정이 있다. 둘 다 실측으로 확인됐다.**

**함정 1 — 경계는 baseline마다 다르다.**
평소 부정률이 높으면 경계 카운트도 올라간다. "24↔25"는 **과거 5% 케이스 전용**이며, 6%·7%에 그대로 쓰면 경계가 아니라 **확실한 미발화**가 된다(예: 사이즈 7%에 24건을 쓰면 p=0.017로 컷오프에서 한참 멀다).

| 과거 부정률 | 경계 카운트(미발화 ↔ 발화) |
| --- | --- |
| **5%** (색상·쿠팡) | **23 ↔ 24** |
| **6%** (소재·지그재그) | **25 ↔ 26** *(본 검증 배치에선 26↔27)* |
| **7%** (사이즈·지그재그) | **28 ↔ 29** *(본 검증 배치에선 29↔30)* |

**함정 2 — 자기참조(self-reference).**
BH 컷오프는 **발화 수에 비례해 움직이는 상대평가**다. 그래서 **G를 경계에 심는 순간 G 자신이 발화 수를 늘려 컷오프를 밀어 올린다**(리뷰 측정 0.0008 → 0.0011). 그 결과 "미발화 쪽"으로 심은 카운트가 컷 안쪽으로 들어와 **발화해버린다.**
→ 실측 확인: 24/200(p=0.000601)을 미발화 의도로 심었으나 컷오프 0.000821 안쪽이라 **발화**. 기각 수도 34 → 37로 증가.
→ 컷오프가 실제로 이동하는 폭은 **컷 바로 위에 귀무 검정이 있는지**에 달려 있어 배치마다 다르다. 이동 여부와 무관하게 **고정점 반복이 필요하다**는 결론은 같다.

⚠️ **따라서 G의 최종 카운트는 단발 계산으로 확정할 수 없다.** §5-5 검산기가 **"심고 → 컷 재계산 → 다시 심고"를 고정점까지 반복**해 확정한다. 아래 표는 그 반복의 **출발값**이다.

- 쿠팡 8% → **16.5%** (33/200, p=0.00045) — 확실 발화
- 네이버 9% → **18%** (36/200, p=0.00038) — 확실 발화
- 지그재그 7% → **위 후보표에서 선택** — BH 임계 근처(경계)
- 의도: 확실한 2채널 + 경계 1채널 → **2채널 편중 ↔ 3채널 전역** 갈림길 관찰

**정답 처리:** 카운트가 고정이면 Fisher p도 고정 → **시드로는 갈리지 않는다.** 실제로 갈리게 하는 것은 **분류기 오차 ±1건**.

**채점 제외 근거:** "정답이 없어서"가 아니라 **정답이 임계값 근처의 임의 설정에 의존해 정확도 지표를 왜곡하므로** 제외. 경계 민감도·분류 오차 취약성 관찰용.
⚠️ 최종 카운트는 §5-5 검산기가 실 배치 컷오프로 확정한다(배치 구성에 따라 소폭 이동).
※ V2 로직상 "보류"는 표본<10일 때만 존재. **p 경계 보류라는 상태는 없다.**

## 4. 채점 방식

**본채점은 oracle 기준이다.** 분류기를 거치지 않고 golden 라벨 카운트를 검정에 직접 입력한다. D·G 케이스는 사건 수가 적어 분류기 오차 1건에 판정이 뒤집히므로, 탐지 로직이 정상인데도 오답 처리되는 구조를 막기 위함이다. 분류 정확도는 **문장 단위 별도 지표**로, end-to-end는 **참고용(전파 측정)** 으로만 쓴다.

**채점 대상 (경계·보류·미탐 제외): 31개**
A(9) + B(6) + C(3) + D(3) + F(3) + 3-1(1) + 3-2(1) + 3-3(1) + 3-4(2) + 3-5(2)

| 지표 | 대상 |
| --- | --- |
| is_anomaly 정확도 | 채점 31개 |
| is_biased 정확도 | **편중형 + 전역형 모두**(편중 오판율까지 측정) |
| main_aspect 일치율 | 참양성 |
| root_cause 정확도 | 스코프 내 편중(§2-A, 3-3) — 3-3은 "미특정" 정답 포함 |
| 탐지 확신도 | SC-030/031, 3-3 |
| 분류 정확도 | 문장 단위 별도(탐지 채점과 분리) |

**채점 제외:** SC-026~028(경계), SC-036(보류), SC-022(미탐), SC-037·038(판정 경계 관찰, §2-I) → "오탐/미탐 성향" 리포트에만 사용.

⚠️ 정확 건수를 plant하면 판정이 결정적이므로 **시드를 반복해도 동일한 결과**가 나온다. **"시드 20벌 × 31케이스 = 620판정"을 표본 수로 주장할 수 없다. 실질 표본은 31케이스다.** 시드 반복이 정보를 주는 쪽은 텍스트가 달라지는 end-to-end 실험이다.

## 5. Mock 생성 참고

### 5-1. 결정론적 생성 원칙

> **카운트(부정 건수·총문의 수)는 전 상품·전 aspect·전 채널에 걸쳐 정확 건수로 심는다(결정론). 랜덤성은 텍스트 표현·시각·순서에만 둔다. 단 SC-024는 일별 배치까지 고정한다.**
> 

**근거**

- 샘플링하면 oracle 채점에서도 D 케이스가 시드의 26~35%에서 뒤집힌다(부록 D). SC-021 기준 P(부정 4건 이상)=35.3%
- 심은 수치가 랜덤이면 **검산 assert가 보장하는 것이 없어진다**
- **BH 임계값 고정 계산도 이 전제 위에서만 성립한다.** BH는 배치 전체 p를 정렬해 임계를 잡으므로 **family 안의 모든 검정**이 결정론이어야 한다
- **분모도 고정 대상이다.** 부정 건수만 고정하고 총문의 수가 흔들리면 p는 여전히 변한다

**원칙 18 — ±1건 강건성 (G·D 제외)**
모든 케이스는 사건 수가 ±1 흔들려도 정답이 유지되어야 한다. **단 G와 D는 예외다.**

- **G:** ±1건에 뒤집히는 것이 케이스의 **목적**이다
- **D:** 저사건(3~5건)이 케이스의 **본질**이라 ±1 강건성이 **원리상 달성 불가능**하다. 강건하게 만들려면 사건 수를 키워야 하는데, 그러면 검정력이 올라가 더 이상 "함정"이 아니게 된다
- **D의 안전성 근거:** oracle 채점 + 정확 건수 plant 하에서는 카운트가 흔들리지 않으므로 **본채점은 안전하다.** end-to-end에서의 뒤집힘은 오답이 아니라 **분류 오차 전파의 관찰 포인트**로 기록한다

### 5-2. SC-024 일별 분포 제어 (유일한 예외)

- §2-F의 일별 표대로 심는다(D7 스파이크 6/29, 나머지 6일 2건씩, 합계 18/200 = 9.0%)
- ⚠️ **`config_anomaly` 스키마에 일별 분포 칸이 없다.** 컬럼 추가(`daily_pattern`=uniform/spike, `spike_day`) 또는 생성기 예외 처리 필요 — **생성기 담당 확인 요청**
- ⚠️ 윈도우 합계만 심으면 **검증이 아니라 가정**이 된다

### 5-3. 상세페이지 수정 이력

- **수정 이력 테이블**(상품ID, 채널, 수정일시, 수정 필드, 이전값/새값) 생성
- **SC-030:** 수정일 = 이상 시작일과 동일. **SC-031 및 나머지 전 케이스: 이력 없음이 기본값**
- ⚠️ **잡음용 변경 이벤트를 SC-030/031의 상품×채널에 배치 금지.** 겹치면 "이력 없음 → 확신도 중간" 정답이 깨진다

### 5-4. 텍스트 생성

- 정의서 패턴 문구를 시드로 LLM 생성(네이버·지그재그 리뷰 어투 참고)
- 원인 분류 케이스는 **최다 원인 비율**을 의도대로 심는다(SC-001=70%, SC-033=30%)
- **D 섹션 문의 텍스트는 aspect가 명백한 문장으로만 생성** — 분류 오차 1건에 판정이 뒤집히므로
- **생성 프롬프트(작가)와 분류 프롬프트(응시자)는 분리 관리.** few-shot 예시는 평가셋 밖에서 사람이 작성(시험지 유출 금지)
- ⚠️ **LLM 생성 건수 확인 필요:** 본 문서 **20건** vs 유지인 Mock 문서 **30건**

### 5-5. 검산 BH 단계 포함

- **자동 검산(필수):**
① 풀 배치 구성 → ② **Fisher 단측(p값만 산출)** → ③ **BH-FDR** → ④ **min_delta AND** → ⑤ 정답 assert
⚠️ **min_delta 탈락 검정도 family에서 제외하지 않는다.** BH를 전체 검정(m=1,464)에 적용한 뒤 min_delta를 AND로 겹친다. delta로 먼저 걸러 family를 줄이면 관측 데이터에 근거해 검정 집합을 고르는 것이 되어 **FDR 보장이 깨지고**, m과 순위가 달라져 컷오프도 바뀐다.
- 이 순서로 하면 **BH 재캘리브레이션을 검산이 자동으로 잡아준다**
- **반드시 실 N 기준으로 검산**
- **±1건 검산 (G·D 제외):** 각 케이스에서 부정 건수를 ±1 했을 때도 정답이 유지되는지 확인
- **G 케이스 — 고정점 반복(필수):** BH 컷오프는 발화 수에 비례하는 상대평가라 **G를 심는 행위 자체가 컷오프를 바꾼다**(자기참조). 따라서 단발 계산으로 확정할 수 없고 아래를 수렴할 때까지 반복한다:

```
① G를 현재 컷오프 기준 경계 카운트에 심는다 (baseline별로 다름)  ② G 포함 풀 배치로 BH 재계산 → 새 컷오프  ③ 새 컷오프로 경계 카운트를 다시 구한다  ④ 카운트가 안 바뀔 때까지 ①~③ 반복 (고정점)
```

고정 정답 assert는 제외하되, **±1건에 뒤집히는지는 확인**한다

- ✅ **−1건 주시 목록 해소** (컷오프 p\*=0.001224 실 배치 검산 완료). 전 참양성이 −1건에도 생존:

| 검정 | 현재 | −1건 p | 판정 |
| --- | --- | --- | --- |
| SC-016 지그재그 | 30/200 | 0.000997 | ✅ 생존 |
| SC-017 쿠팡 | 33/200 | 0.000848 | ✅ 생존 |
| SC-017 지그재그 | 30/200 | 0.000997 | ✅ 생존 |
| SC-032 쿠팡 | **25/200**(상향 후) | 0.000601 | ✅ 생존 |

### 5-6. 기타

## 부록 E. BH-FDR family 변경 기록

> 아래 V3.1 수치는 **전환 전 전역 family 실험 기록**이다. 2026-08-13부터 운영·평가는 상품별 family(최대 36)를 사용한다. 전체 1,464검정은 감사용 총량이며 하나의 BH family가 아니다.

**V3.1의 오류:** *"운영 규모(m=1,440)에서는 임계가 q/m=3.5e-5라 SC-001(p=0.0001)조차 죽는다"* 고 적었으나 **이는 틀렸다.정정:** q/m은 **순위 1등에게만** 적용되는 최소 임계다. BH는 **step-up** 절차라 임계가 발견 수에 비례해 올라간다 — 순위 k의 임계는 **(k/m)×q**. 우리 배치엔 참양성이 30개 이상 있어 **실효 컷오프가 ~0.0006까지 상승**하고, SC-001은 운영 규모에서도 여유 있게 생존한다.

**전환 전 family: 평가 배치 = 운영 동형 풀 배치**
평가 배치를 "골든 라벨 행 수(≈108)"로 잡았던 것도 오류였다. 실제로는 케이스 상품 **38**개도 각각 **36검정을 전부** 돌린다(이상을 심은 aspect 외 35개는 귀무 검정으로 함께 돌아감).

| 구성 | 검정 수 |
| --- | --- |
| 케이스 상품 **38** × 36검정 | 1,368 |
| 배경 상품 4 × 36검정 | 144 |
| 보류 채널 제외 — (상품,채널) 4개 × 12검정 | − 48 |
| **합계** | **1,464** = 운영 하루와 동일 |

→ 이 구성은 평가에서 참양성이 많이 함께 존재할 때만 전역 family의 BH 컷오프가 완화되어, 실제 일별 데모에서 탐지가 사라지는 평가·운영 괴리를 만들었다. 현재는 검정 결과와 무관하게 사전 정의되는 `product_group_id`로 family를 나눈다.
