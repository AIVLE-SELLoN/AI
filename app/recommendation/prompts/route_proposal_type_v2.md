# 개선안 도구 라우팅 (v2)

Agent3의 핵심 판단 지점. 규칙(키워드 매칭)이 아니라 **모델이 tool을 직접 호출해서**
copy_draft/image_guide를 결정한다 — 이걸 규칙 기반으로 바꾸면 다시 workflow로
후퇴한다(CLAUDE.md 참고). 여기서 고른 tool에 따라 이후 생성 프롬프트와 근거 소스가
통째로 갈린다(copy_draft_v1.md / image_guide_v2.md).

구버전 삭제 금지 — 개선 시 `route_proposal_type_v3.md` 신규 생성.

**v1 대비 변경(2026-08-09)** — v1은 CS 쪽 근거로 통계 요약 한 줄만 보여줬다. 그래서
모델이 "CS 근거가 실제로 쓸 만한가"를 판단할 수가 없었다(요약은 원인이 뭐든 항상 같은
모양으로 존재하므로). v2는 실제 CS 원문을 같이 보여준다.

한쪽 근거가 "정보 없음"인 채로 그쪽 도구를 고르면 `run()` 이 생성을 건너뛰고 개선안 없이
끝난다(근거 0건이라 만들 게 없다). 그래서 아래 "둘 중 있는 쪽을 고르라"는 지시가 비용
문제가 아니라 **셀러가 개선안을 받느냐 마느냐**를 가른다.

---

## 지시

당신은 이커머스 이상탐지 결과를 보고 어떤 개선안 조치가 적합한지 판단하는
어시스턴트입니다. 아래 두 근거 후보를 비교해서, 제공된 tool 중 하나를 반드시
호출하세요.

- 상세페이지 원문에 실제로 고칠 만한 내용이 있으면 → use_copy_draft
- 원인이 사진·조명·이미지 표현처럼 촬영 결과물 문제면 → use_image_guide
- 판단이 애매하면 두 근거의 **유무**를 기준으로 삼으세요. 어느 쪽이든 "정보 없음"이면
  그쪽은 인용할 원문이 없다는 뜻이라 개선안을 만들 재료가 없습니다.
  - 상세페이지가 "정보 없음"이면 → use_image_guide 쪽에 무게
  - CS 문의 원문이 "정보 없음"이면 → use_copy_draft 쪽에 무게

reason 인자에는 왜 이 도구를 골랐는지, 아래 근거 중 무엇을 근거로 판단했는지
한 문장으로 쓰세요.

## 입력

- 상세페이지 원문 (컬렉션1, copy_draft 근거): {detail_text}
- CS 문의 원문 (image_guide 근거): {cs_quotes}
- CS 문의 통계 (맥락): {cs_summary}
