먼저 돼 있어야 한다 (`scripts/seed_vectordb.py`).

```bash

```

⑤는 **비용이 드는 부분을 플래그로 분리**해뒀다. 아무 플래그 없이 돌리면 $0 구간만 돈다.

```bash
python eval/run_recommendation_eval.py                # Retrieval hit rate만, $0
python eval/run_recommendation_eval.py --grounding    # + Grounding precision
python eval/run_recommendation_eval.py --rag-baseline # + RAG 유무 비교
python eval/run_recommendation_eval.py --routing      # + 라우팅 정확도 (golden 15건)
python eval/run_recommendation_eval.py --routing-real # + 라우팅 정확도 (실제 CS 201건)
```

⑦은 `--dry-run` 으로 표본만 눈으로 볼 수 있다(임베딩 호출 0회).

```bash
python eval/run_embedding_eval.py           # 두 모델 A/B, $0.0001 미만
python eval/run_embedding_eval.py --dry-run # 표본만 출력, $0
```

⚠️ **⑤의 "$0" 구간도 이제 `LLM_API_KEY` 가 있어야 돈다**(2026-08-09부터). 임베딩 함수가
컬렉션 설정의 일부라, 키가 없으면 임베딩이 필요 없는 컬렉션1 `get()` 조회까지 막힌다.
**비용은 그대로 $0** 이다 — 키를 읽을 뿐 부르지 않는다.

> 인용하거나 그 명령만으로 같은 호출 구성을 재현하면 안 된다.
>
> 현재 캐시 파일명에는 `chunk_size`가 없다. 그래서 별도의 chunk 20 실험을 실행해도
> chunk 100 예측을 그대로 읽을 수 있다. 이번 결과의 출처는 위처럼 문서로 고정하고,
> **다음 신규 측정 전에** 최초 `chunk_size`를 캐시 키와 회귀 테스트에 포함한다.

> 유출은 현재 실험② 케이스의 색상·사이즈·소재 슬롯과 안 겹치므로 **현재 실험②의

> 않는다. 운영 탐지는 기타·오배송도 처리하므로 일반적인 "탐지 영향 없음"으로 넓혀

## ③ 실측 결과 (2026-08-05 · classify_aspect_v5 · --only-negative · 배치) — 재생성 전 데이터

실제로 소비하는 값은 sentiment=-1뿐이라, 중립 포함 전체를 재는 aspect_f1은 대시보드·
리포트용으로 용도를 내리고 병기만 한다.

⚠️ **둘 다 "완전히 온전한" 실행은 아니다** — 300건 표본은 규모가 작아 신뢰구간이
넓고, 전체(96,531건) 실행은 중간에 배치 실패로 55건(0.06%)이 무응답 처리됐다.

**규모가 다른 두 실행이 서로를 검산한다** — 표본을 322배(300→96,531)로 늘려도
recall 97.3%→96.8%, ② 99.3%→98.9%로 이탈이 작다. 300건 결과가 우연이 아니었다는
근거가 된다.

⚠️ **단, FPR만은 300건으로 판정할 수 없다.** 오탐은 특정 템플릿 하나에서만 나오는데,
그 템플릿이 비부정 150건 표본에 기대 6.8건 들어오고 뒤집힘률이 1.60%라 **기대 오탐이
0.11건**이다. 실제 오탐이 있어도 300건에서 FPR=0%가 나올 확률이 90%다. 300건의
`FPR 0.0%`는 "오탐이 없다"가 아니라 **"볼 검정력이 없다"**로 읽어야 하고, FPR 판정에는
전량이나 해당 템플릿 과표집 표본이 필요하다.

⚠️ **전체 실행의 오탐 65건은 전부 같은 문장이다** — `"배송 조회가 안 되는데 확인
부탁드려요."`(코퍼스 4,058건, 골든 `기타/0`). 이 문장은 프롬프트 예시20에 `기타/0`으로
그대로 인용돼 있는데도 1.60%(65/4,058)가 부정으로 샌다. 38행 최우선 규칙("부정적 경험이면
무조건 부정")이 밀고 있기 때문이다.

즉 예시20은 이 4,058건을 중립으로 붙들고 있는 **앵커**다. 리뷰에서 지적된 "분자 +57%"는
현재 수치가 아니라 **이 앵커를 제거했을 때의 상한**이며, 오탐이 전부 그 템플릿에서 나온다는
사실이 오히려 그 경고의 근거다. 따라서 few-shot 유출은 프롬프트 예시를 바꾸는 대신
평가에서 거르는 방향으로 처리한다(노션 [실험③ 지표 재설계] §6).

⚠️ **표본 설계 주의** — `--only-negative`는 부정 N + 비부정 N을 균형 추출한다(PR
리뷰 반영, 2026-08-05). 부정만 뽑으면 fp·tn이 구조적으로 0이 되어 "모든 문의를
부정으로 뭉개는" 모델도 precision 100%가 나오는 함정이 있었다 — 지금은 FPR까지
같이 측정된다(`tests/test_run_classify_eval.py`에 회귀 테스트로 고정됨).

⚠️ **전체 실행의 55건 무응답은 배치 실패**(API 처리 중 토큰/연결 문제로 일부 청크
누락)이지, 프롬프트나 채점 로직 문제가 아니다 — `run_classify_eval.py`가 실패

### 후속 방향

**1번과 6번은 2026-08-11 완료했다.** 프롬프트2 본체는 바꾸지 않았고, 나머지는 새

1. ✅ **`TARGET_MAP` 확장 — `신축성`·`마감` → 소재, `길이` → 사이즈.**
   프롬프트2 28행·예시8·예시12가 **이미** 그렇게 정의돼 있다. 규칙을 느슨하게 하는 게

2. **`두께`·`무게`·`냄새` 를 어느 쪽으로 할지 정한다 — 스펙 공백.**
   프롬프트2에 문장이 없어서 모델이 매번 다르게 답한다. 소재에 넣기로 하면 FP 10건이
   더 걷힌다. **프롬프트 문구가 필요하니 실험③ 이후.**
3. **`품질`·`촉감` 은 규칙을 안 고친다.** 42행·예시1 주석이 이미 "무시"라고 명시했는데
   8건이 샜다 — 규칙 부재가 아니라 **준수 실패**라, 문구 추가가 아니라 예시 보강 대상.
4. **부정우선 예외를 골든에 자동 반영하는 건 원리적으로 불가능하다.** 71630 라벨은
   낱개 polarity 뿐이라 "화자가 스스로 사소하다고 프레이밍했는가"가 라벨에 없다.
   선택지는 (a) 3건을 사람이 손으로 판정해 예외 목록에 박기, (b) 0.13%라 한계로 기록만.
   **(b) 권장** — 21건짜리 스코프 결함을 놔두고 3건을 고치는 건 순서가 틀렸다.
5. **프롬프트1의 예외는 `mixed_signal` 없이 동작한다.** CS는 스키마상 `None` 고정이라
   예외 적용 시 `1` 만 남고 혼합이었다는 정보가 사라진다. 탐지가 `-1` 만 소비하므로
   지금 당장 해는 없지만, 프롬프트1 예외 규칙의 효과는 **어떤 골든으로도 측정되지 않는
   상태**다(③ 골든에 컬럼 자체가 없다).
6. ✅ **3회 독립 반복 + 회차 내부 무응답 재시도 + 전체 예측 저장 + 자동 스크럽.** 결과
   파일만으로 기존/정정 골든의 paired 재채점이 가능하고, 원문은 저장하지 않는다.

**실행 순서 주의** — ④ 측정 자체는 `data/` 와 무관해 지금 병렬로 가능하지만,
**④ 결과로 프롬프트2를 고치면 실험②의 새 기준선이 그 자리에서 무효가 된다**(②가

## 비용 통제 4원칙

1. **반복 실험은 oracle 모드로** — 정답 라벨을 직접 입력해 LLM 을 안 태운다 ($0)
2. **분류는 배치 호출** — 건당 호출하면 비용 2배 + 속도 제한 초과
3. **분류 결과는 시드별 캐싱** — 같은 걸 두 번 돌리지 않는다
4. **모델 티어링** — 호출 많은 분류는 저가 모델, 호출 적고 중요한 개선안 생성만 상위 모델

## 원칙

- **`data/golden/` 은 `eval/` 만 읽는다.** `app/` 코드가 import 하면 컨닝이다.
  - 예외 1건: **`scripts/golden_inputs.py`** (2026-08-06 신설). `app/batch/daily.py` 가
    골든을 직접 읽고 있던 것을 `app/` 밖으로 뺀 것이다. 배치를 평가·재현으로 돌릴 때만
    `--input-source golden` 으로 주입하고, 그러면 요약이 oracle 경고를 함께 낸다.
    `app/` 은 여전히 `data/golden/` 을 읽지 않는다 — 원칙 위반이 아니라 원칙을 지키려고
    만든 파일이므로 지우지 말 것. rawDB `classified_item` 이 생기면 역할이 사라진다.
- **재현 가능해야 한다** — 결과와 함께 **실행일·모델명·프롬프트 버전·시드·표본 수 n**
  다섯 개를 반드시 기록할 것. 하나라도 빠지면 발표에 못 쓴다.
- **분모를 밝힐 것.** "100%"가 아니라 "15/15 (100%)"로.
- **정답지를 우리 코드로 만들지 말 것.** 채점 대상으로 정답을 만들면 자기 코드로
  자기를 채점하는 순환이 된다 (①의 `build_golden_anomaly.py` 참고).
- **오답 문장을 이 문서에 적지 말 것.** 유형·건수까지만 쓴다. 이 문서는 커밋되므로
  적는 순간 프롬프트 작성자가 그것을 보고 few-shot 예시를 만들게 되고, 그러면
  `mock data 정의서` §672("few-shot 예시는 평가셋 밖에서 작성 — 시험지 유출 금지")가
  깨진다. 2026-08-06 에 실제로 일어났고(②절 참고), **그렇게 만든 예시는 효과가 없었다.**
  문장이 필요하면 각자 `--diagnose` 를 돌린다 — LLM 0회다.
