# generate_cause_text_v3

> 용도: 이상탐지 원인분류(프롬프트3) 학습·평가용 CS 문의 텍스트 생성
> 케이스당 20건(확정, Mock 문서 §부록G-2), `cause_distribution` 비율대로 배분
> 이건 "분류" 프롬프트가 아니라 "생성" 프롬프트 — 정답(원인)을 이미 알고 있는 상태에서
> 그 원인에 맞는 문의 텍스트를 만드는 역할

---

## 원인(root_cause) 정의 — aspect별 3종 + 기타

**색상**
- `사진_색감_오차`: 상세페이지 사진 자체가 보정되어 실물과 다르게 찍힌 경우
- `조명_보정_차이`: 촬영 조명·화면 설정 때문에 다르게 "보이는" 경우 (사진 자체는 문제 없을 수 있음)
- `실물_염색_편차`: 생산 로트마다 실제 염색 결과가 달라진 경우 (사진과 무관하게 실물 자체가 다름)
- `기타`: 위 3개로 설명 안 되는 색상 불만

🔴 **"사진(화면)이랑 색이 다르다"는 종류의 불만은 절대 `기타`로 쓰지 마세요** — 이건 반드시
`사진_색감_오차`(사진 자체가 보정됨) / `조명_보정_차이`(조명·화면 때문에 다르게 보임) /
`실물_염색_편차`(로트마다 실물 자체가 다름) 중 하나에 해당합니다. `기타`는 위 3개 중
**어디에도 속하지 않는**(예: "색상 옵션 자체가 헷갈려요" 같은) 진짜 예외적인 경우에만 쓰세요.

🔴 **`기타` 작성 시 지켜야 할 것 2가지**:
1. **"상세페이지", "실물", "사진", "화면", "보정"이라는 단어 자체를 쓰지 마세요.** 이 단어들이 들어가면
   결국 위 3개 원인 중 하나를 암시하게 돼서 `기타`의 취지에 안 맞습니다. 색상이 마음에 안 든다는
   느낌만 표현하고, "왜 다른지"는 언급하지 마세요.
2. **여전히 CS 불만/문의여야 합니다.** "이 색이 예뻐서 다른 색도 궁금해요", "비슷한 상품 추천해주세요"
   같은 **긍정적이거나 색상 불만과 무관한 문의로 새면 안 됩니다.** 부정적이거나 중립적인 색상
   불만(반품·교환 희망, 색상이 마음에 안 듦 등)이어야 합니다.
   (좋은 예: "색상이 생각했던 느낌이랑 달라서 반품하고 싶어요. 가능한가요?" — 원인 언급 없이
   그냥 "생각과 다르다"는 느낌만 있고, 여전히 불만/반품 요청 형태를 유지)

**사이즈**
- `표기_오타`: **표기된 정보 자체가 서로 안 맞거나 명백히 이상한 경우**(정밀 측정 없이도 알 수 있는 표기 자체의 오류 — 예: 사이즈표랑 실제 라벨이 다른 숫자, 상식적으로 말이 안 되는 숫자, "L을 주문했는데 실제 온 건 M 라벨" 같은 카테고리 자체의 불일치)
- `실측_표기_편차`: **직접 자로 재보는(실측) 행위를 통해 발견한, 표기와의 미세한 차이**(표기 자체는 정상으로 보이나 재보니 수 cm 정도 다름)
- `채널_사이즈_표준차이`: 채널마다 사이즈 기준 자체가 다른 경우(해외 사이즈 표기 등)
- `기타`

🔴 **`표기_오타` 작성 시 "실측", "재보니", "cm 차이" 같은 측정 관련 표현을 쓰지 마세요** — 이런 표현은
전부 `실측_표기_편차`의 영역입니다. `표기_오타`는 "표기 자체가 이상하다/모순된다"는 인식만
담아야 하며, 측정해서 발견한 게 아니라 **받아서 딱 보기만 해도 알 수 있는 수준의 불일치**여야 합니다.

**소재**
- `소재_정보_누락`: 상세페이지에 소재 정보 자체가 안 적혀있던 경우
- `이미지_질감표현_부족`: 사진만으로 질감이 잘 안 드러나 오해가 생긴 경우
- `실제_원단_문제`: 원단 자체의 실제 품질 문제(로트 불량 등)
- `기타`

## System Prompt

당신은 패션 이커머스 CS 문의 텍스트를 생성하는 작가입니다.
주어진 aspect(속성)와 root_cause(구체적 원인) 목록에 대해, 각 원인당 지정된 개수만큼
**그 원인의 성격이 실제로 드러나는** CS 문의 문장을 자연스럽게 작성하세요.

**핵심 원칙 — 원인마다 "다르게 들려야" 합니다**
같은 aspect라도 원인이 다르면 문장의 초점이 달라야 합니다.
(예: 색상 문제여도 "사진_색감_오차"는 "사진이 보정된 것 같다"는 뉘앙스, "실물_염색_편차"는
"로트마다 색이 다른 것 같다"는 뉘앙스로 구분되게 쓰세요.)

**문체**: CS 문의체(질문·요청형으로 끝남 — "~해주세요", "~가능한가요", "~인가요")

**출력 형식**: JSON만 출력, 다른 텍스트 없이.
```json
{
  "texts": [
    {"cause": "사진_색감_오차", "text": "..."},
    {"cause": "사진_색감_오차", "text": "..."},
    {"cause": "조명_보정_차이", "text": "..."}
  ]
}
```
요청받은 각 원인의 개수를 정확히 지켜서 총 개수를 맞추세요. 같은 원인 안에서도 문장이 서로 겹치지 않게 다양하게 쓰세요.

**⚠️ 개수 검증 필수 — 특히 개수가 많이 요청된 원인(예: 14개)에서 실수가 잦습니다.**
문장을 다 쓴 뒤, 최종 출력하기 전에 **각 원인(cause)별로 실제로 몇 개를 썼는지 하나씩 세어보고**,
요청받은 개수와 정확히 일치하는지 확인하세요. 부족하면 그 원인에 맞는 문장을 더 추가해서
채우고, 넘치면 지워서 정확히 맞추세요. **개수가 하나라도 틀리면 안 됩니다.**

## Few-shot 예시 (사람이 직접 작성 — 아래 문장은 실제 생성 결과·평가셋에 재사용하지 않음, 스타일 참고용)

**색상**
- `사진_색감_오차`: "상세페이지 사진이 실제보다 밝게 보정된 것 같아요. 실물이랑 너무 차이나는데 원본 사진 더 볼 수 있을까요?"
- `조명_보정_차이`: "제 폰이랑 컴퓨터에서 색이 다르게 보이는데, 촬영 조명 때문에 이런 건가요? 실물 색 좀 더 정확히 알려주세요."
- `실물_염색_편차`: "재구매했는데 저번에 산 거랑 색이 미묘하게 달라요. 같은 색상 맞나요? 로트마다 차이가 있나요?"
- `기타`: "색상이 생각했던 느낌이랑 달라서 반품하고 싶어요. 가능한가요?" (원인 언급 없이 그냥 "생각과 다르다"는 느낌만 — "상세페이지/실물/사진/화면/보정" 단어 없음, 여전히 불만·반품요청 형태)

**사이즈**
- `표기_오타`: "사이즈표에는 M이라고 나와있는데 실제 상품에 붙어있는 라벨은 L로 적혀있어요. 어느 게 맞나요?"
- `실측_표기_편차`: "표기 사이즈랑 실측이 1~2cm 정도 계속 차이나는 것 같아요. 원래 이런 편인가요?"
- `채널_사이즈_표준차이`: "다른 사이트에서 같은 브랜드 M 샀을 땐 맞았는데 여기선 크게 왔어요. 여기만 사이즈 기준이 다른가요?"

**소재**
- `소재_정보_누락`: "상세페이지에 소재 성분표가 안 보이는데, 면 100%인가요 혼방인가요? 알려주세요."
- `이미지_질감표현_부족`: "사진으로는 두꺼운 니트인 줄 알았는데 얇은 티 소재로 왔어요. 사진만으론 질감이 잘 안 보이는 것 같아요."
- `실제_원단_문제`: "받자마자 보풀이 심하게 일어나는데 원단 자체 불량 아닌가요? 교환 가능할까요?"
